# 圣诞活动 —— 枫叶节 / 维萨尔节 玩法与实现说明

> 官方活动复刻。原型为 `bms/Script/xmas.s`（`claws_present` / `pongo_present` / `suzy_lost`）
> 最后更新：2026-10-17
> 相关脚本：`9201030.js`、`9201091.js`、`9201093.js`、`9300010.js`
> 相关数据库：`db/migration/V1.14.4__create_xmas_present_event.sql`

---

## 1. 一句话说明

圣诞活动是**二选一的阵营活动**：玩家在小苏茜那里拿到"心愿单"后，要么交给**梅普克劳斯**（枫叶节），要么交给**奥蓬戈**（维萨尔节）——**一个角色只能选一边**。选定后去刷与自己等级相符的怪物，捡对应颜色的**礼物盒**，回来按批次兑换奖励，每天最多 100 个。

## 2. 参与流程（玩家视角）

| 步骤 | 做什么 | 在哪 |
|---|---|---|
| 1 | 找**小苏茜**（NPC 9201093）聊天，拿到道具 `4031877` 心愿单 | 新叶城 `600000000` |
| 2 | 把心愿单交给二选一：**梅普克劳斯**（9201030）或 **奥蓬戈**（9201091） | 幸福村 `209000000` / 新叶城 `600000000` |
| 3 | 交付后阵营锁定：枫叶节完成 **4997**，维萨尔节完成 **4998**；同时拿到对应节日的帽子 | — |
| 4 | 去打怪，捡"礼物盒"（掉落跟**怪物等级**走，见第 3 节） | 任意地图 |
| 5 | 回对应 NPC，按 `10 / 20 / 30 / 40 / 60 / 90 / 100` 个一批兑换 | — |
| 6 | 每天最多交 100 个；交够 100 个当批可拿一次性大奖 | — |

> ⚠️ 阵营是**互斥**的：
> - 选了维萨尔节（4998 完成）后再找梅普克劳斯，她会说"你今年决定过维萨尔节了"，不能兑换。
> - 选了枫叶节（4997 完成）后再找奥蓬戈同理。
> - 30 个及以上的档位**必须先完成对应阵营的前置任务**（4997 或 4998），否则只会听到"先去找小苏茜"。

## 3. 礼物盒掉落（按**怪物等级**分档）

| 怪物等级 | 礼物盒 ID | 中文名 |
|---|---|---|
| 10 – 20 | `4031443` | 红/绿 礼物盒 |
| 21 – 30 | `4031440` | 红/白 礼物盒 |
| 31 – 40 | `4031441` | 红/蓝 礼物盒 |
| 41 – 60 | `4031439` | 蓝/白 礼物盒 |
| 61 + | `4031442` | 白/绿 礼物盒 |

- **10 级以下的怪物不掉**（活动面向 10 级以上玩家）。
- 玩家自己是什么等级，就必须捡**对应档位**的礼物盒——NPC 只收自己等级段那一种，其它颜色的收不了。
  所以"去打和自己等级相符的怪"是必须的。
- 覆盖了 `wz/Mob.wz` 里全部 **788** 只怪中等级 ≥10 的 **731** 只，明细见迁移 SQL。

### 掉落开关（重要）

掉落**默认是关的**，只有"活动参与者"才会掉：

| 任务 8209 状态 | 结果 |
|---|---|
| 未接（0）—— 没参加活动 | **不掉**。而且不是"看得见捡不起来"，是**连地上都不会出现**（发包被过滤） |
| 进行中（1）—— `"ing"` | 掉 |
| 已完成（2）—— `"end"` | 不掉 |

- 触发时机：**只要你是参与者（4997 或 4998 已完成），每次点开这两位 NPC 的对话，脚本就会把 8209 切成"进行中"**（`syncDropSwitch()`，幂等）。
- 所以顺序上：先找 NPC 接任务 → 才会开始掉。这正是想要的效果。

### 掉率

- 分母是 `1000000`，迁移里默认 `@present_chance = 10000`（**1%**）。
- 实际概率 = `chance / 1000000` × **频道掉率** × **怪物卡片加成**。
- 想改：直接改 `V1.14.4` 里的 `SET @present_chance = ...;` 后重跑，或者热改：

```sql
UPDATE `drop_data` SET `chance` = 200000 WHERE `questid` = 8209;  -- 20%
```

## 5. 每日上限与 24 小时重置

- 每天最多兑换 **100 个礼物**（按个数累加，可拆成多批）。
- 记录存在**任务自定义数据**里：

| 任务 ID | 内容 |
|---|---|
| `8200` | 上次兑换时间戳（毫秒） |
| `8201` | 当日已兑换礼物总数 |

- 超过 24 小时后再来兑换，会**先把上限清零**，然后提示"请等我清零后再来"，需要**再点一次 NPC**。（这是原型行为，原样保留）

### 一次性大奖

| 阵营 | 奖励 | 只领一次标记 |
|---|---|---|
| 枫叶节 | `1432046` 圣诞树手杖 ×1 | 任务 `8202` = `"end"` |
| 维萨尔节 | `1442061` 星纪圣诞仙人掌 ×1 | 任务 `8203` = `"end"` |

领过之后再想走 100 档，会被拦下并提示"每位冒险家只能得到一次，可以试试 90 个碰运气"。

> 注：奥蓬戈 100 档的"已领过"提示文案，原型沿用的是梅普克劳斯的说法（提到"枫叶圣诞树"），实际给的是仙人掌。为保持还原度暂未改动；想改只需动 `9201091.js` 里的 `CACTUS_ALREADY_MSG`。

## 6. 精神道具：`4031878` 与 `4031879`

| 道具 | 中文名 | 来源 |
|---|---|---|
| `4031878` | 枫叶圣诞精神之星（Star of Maplemas Spirit） | 梅普克劳斯处**每次兑换**按 10:1 附带赠送 |
| `4031879` | 反转圣诞欢乐宝珠（Orb of Versalmas Cheer） | 奥蓬戈处**每次兑换**按 10:1 附带赠送 |

规律：交 10 个礼物给 1 颗，60 个给 6 颗，100 个给 10 颗（即"每 10 个礼物 1 颗"）。

### 原版里它们是干什么的

**没有兑换商店。** 它们的唯一用途是"活动结束时的阵营结算凭证"，由 **Cody（NPC `9200000`，脚本名 `X2007give`）** 结算，逻辑在 `bms/Script/GLevent.s`：

1. 用任务 `8211` 作为"已结算"标记。
2. 如果玩家站**枫叶节**（4997 已完成）→ **只数 `4031878`**，按数量分档给经验（按等级段 8-10 / 11-30 / 31-70 / 71-120 / 121+）：

   | `4031878` 数量 | 各等级段经验 |
   |---|---|
   | 1 – 40 | 84 / 236 / 10848 / 217597 / 3134424 |
   | 41 – 99 | 168 / 472 / 21696 / 435194 / 6268848 |
   | ≥ 100 | 336 / 944 / 43392 / 870389 / 12537697 |

3. 如果玩家**不是枫叶节阵营**（维萨尔节 / 没选）→ `4031878`、`4031879`、`4031880` **全部没收**，只给 **`2022278` 煤块 ×1**（纯搞笑道具，回 1HP/1MP），文案是"尽管你尽力了，但枫叶节赢了，所以你没有奖励"。
4. 两种结果最后都会置 `8211 = "end"`，并调用 `takeawayitem` **把 `4031878` / `4031879` / `4031880` 全部销毁**。

> 小坑：原脚本里这一句写作 `takeawayitem;`（函数声明是 `function takeawayitem {`，没有参数列表），
> 与 `GiveExp(...)` 那种带括号的调用写法不一致。**如果它其实没被调用，精神道具会一直留在背包里**——
> 移植时建议写成明确的 `removeItems(...)` 调用，不要照抄这个写法。

> ⚠️ 所以你在 `GLevent.s` 里看到的"回收"（`takeawayitem`）**本身就是销毁，不是兑换**。
> 而且那个"谁赢了"是**硬编码枫叶节获胜**的（`GiveExp()` 的文案写死 "Maplemas has won"），
> 脚本并不会真的去比较两种道具的数量——胜负由运营在活动结束时人工决定。

### 本服现状（重要）

- **`X2007give` 结算脚本没有移植**：`scripts-zh-CN` 下没有对应 JS，`9200000.js` 也不存在。
- 因此在当前服务器上，**`4031879`（以及 `4031878`）目前没有任何用途**，只会一直堆在 ETC 背包里。

如果想让它有用，有三条路可选（都还没做）：

1. **移植 Cody 结算**：在 `9200000.js` 里实现 `X2007give`，需要先定：谁赢？固定枫叶节赢、固定维萨尔节赢、还是真的按全服玩家持有量比较。
2. **做成兑换商店**：另起一个 NPC，把宝珠按比例换成实物/金币（比原版更适合长期运营）。
3. **当纪念品**：不处理，仅作为活动收集品。

### 7.2 任务 ID 一览

这些任务在 `Quest.wz` 里**并不存在**，是借用"任务自定义数据"当键值表用：

| 任务 ID | 用途 | 写法 |
|---|---|---|
| `4994` | 小苏茜前置 | 真实任务（Quest.wz） |
| `4997` | 枫叶节阵营（完成 = 已交付心愿单） | 真实任务 |
| `4998` | 维萨尔节阵营 | 真实任务 |
| `8200` | 上次兑换时间戳 | `customData` |
| `8201` | 当日已兑换数量 | `customData` |
| `8202` | 枫叶树是否已领 | `customData` = `"end"` |
| `8203` | 仙人掌是否已领 | `customData` = `"end"` |
| `8208` | 农历新年红包掉落开关 | `customData` = `"ing"` / `"end"` |
| `8209` | **本活动礼物盒掉落开关** | `customData` = `"ing"` |

> `QuestRepository.getInstance()` 会自动补齐缺失的任务定义，所以**不需要往 `quest` / `queststatus` 插任何数据**。

### 7.3 掉落开关原理

`org.gms.client.Character#needQuestItem(questid, itemid)`：

```
questid <= 0        → true（恒掉）
状态 0（未接）      → 查 Quest.wz"接取所需道具"；8209 无此数据 → MIN_VALUE → false
状态 1（进行中）    → 查 Quest.wz"完成所需道具"；8209 无此数据 → MAX_VALUE → true（无限掉）
状态 2（已完成）    → false
```

并且 `MapleMap#spawnDrop()` 与 `MapItem#sendSpawnData()` 都会用 `needQuestItem` **过滤发包**，
所以未参加的玩家是"地上根本看不到"，不是"看得见捡不起来"。

⚠️ **状态（status）才是指挥棒，不是 customData。**
改状态必须用 `cm.updateQuestCustomData(id, "ing"|"end")`；
只用 `cm.getQuestRecord(id).setCustomData(...)` 只写字符串、不动 status，**拦不住掉落**。

### 7.4 与"换成 questid=0"的区别

`questid = 0` 表示"恒掉"，**没接任务的玩家也会捡到礼物盒并塞满背包**——这正是本项目早期版本的问题，已修正。

## 8. 运维与调整

### 改掉率

```sql
UPDATE `drop_data` SET `chance` = 200000 WHERE `questid` = 8209;   -- 20%
```

### 临时关闭整个活动

```sql
UPDATE `drop_data` SET `chance` = 0 WHERE `questid` = 8209;
```

（注意：NPC 对话仍可兑换，只是不再掉礼物盒。想连兑换一起关，得改脚本或加活动时间判断。）

### 重置某个玩家的活动进度

```sql
DELETE FROM `queststatus`
WHERE `characterid` = ? AND `quest` IN (8200, 8201, 8202, 8203, 8209);
```

### 查某人当前状态

```sql
SELECT `quest`, `status`, `custom_data` FROM `queststatus`
WHERE `characterid` = ? AND `quest` IN (8200, 8201, 8202, 8203, 8209, 4994, 4997, 4998);
```

正常表现：

| 场景 | 8209 | 8201 | 8200 |
|---|---|---|---|
| 没参加 | 无记录（或 0） | 无记录 | 无记录 |
| 参加了没换过 | `1 / "ing"` | 无记录 | 无记录 |
| 今天换了 30 个 | `1 / "ing"` | `"30"` | 时间戳 |

### 常见问题排查

| 现象 | 原因 |
|---|---|
| 打怪不掉礼物盒 | ① 怪物等级 <10；② 没跟 NPC 说过话（8209 未开）；③ 没完成 4997/4998（不是参与者） |
| 掉了但捡不起来 | 概率极小；通常是 8209 状态不对，重开一次 NPC 对话即可 |
| 提示"先去找小苏茜" | 想用 30 档以上但 4997/4998 未完成 |
| 提示"你今年决定过维萨尔节了" | 阵营互斥，找错 NPC 了 |
| 提示"已经超过今天 100 个" | 当日已达上限，或跨 24h 后需要再点一次 NPC 触发清零 |
| 提示"背包格数已满" | 预检 `canHold` 未通过，清一下 ETC/消耗栏 |
